# Decisions

주요 의사결정을 날짜별로 기록한다. 아래 내용은 초기 방향이며 구현 완료를 의미하지 않는다.

## 2026-10-01 — 초기 프로젝트 방향

### 프로젝트 범위

- QA 연습에 필요한 기능만 구현한다.
- production-grade 이커머스 구축은 목적에 포함하지 않는다.
- 이번 작업은 문서 초기 세팅까지 진행한다.

### 실제 PG 미사용

- 실제 결제 연동은 하지 않는다.
- 테스트 가능한 결제 성공/실패 시뮬레이션을 구현할 예정이다.
- 이유: 결제 인프라 구축은 프로젝트 핵심 목표가 아니다.

### SQLite 사용 예정

- DB로 SQLite를 사용할 예정이다.
- 이유: 별도 DB 서버 구축 비용 없이 SQL과 데이터 검증을 연습할 수 있다.

### UI 범위

- 포트폴리오 캡처가 가능한 수준의 깔끔한 UI까지만 구현한다.
- 복잡한 애니메이션이나 디자인 시스템 구축은 범위에서 제외한다.

미확정 비즈니스 정책은 [Requirements의 Open Question](requirements.md#open-question)에서 관리하며, 결정 후 관련 문서에 반영한다.

## 2026-10-01 — 주문·결제·쿠폰 정책 확정

사용자 결정에 따라 다음 정책을 확정 요구사항에 반영했다.

- OQ-01: 한 주문에 쿠폰을 중복 사용할 수 없다.
- OQ-02: 결제 실패 후 동일 주문의 재결제가 가능하다.
- OQ-03: 재고는 주문 생성 시점에 차감한다.
- OQ-05: 동일 사용자가 동일 쿠폰을 재사용할 수 없다.

취소 가능 시간 제한(OQ-04)은 미확정으로 유지한다. 결제 실패·미결제 시 재고 처리(OQ-06)와 쿠폰 사용 확정 및 이력 처리(OQ-07)는 추가 확인 사항으로 기록했으며, 임의로 결정하지 않았다.

## 2026-10-01 — 취소 시간 및 재고·쿠폰 처리 원칙 반영

후속 사용자 답변에 따라 다음 원칙을 반영했다. 앞선 기록의 미확정 항목 중 아래 내용은 이 결정으로 갱신한다.

- OQ-04: 취소 가능 시간은 1시간이다.
- OQ-06: 미결제 상태에서는 차감한 재고를 유지하고, 주문 실패 시 즉시 복구한다. 재결제에도 동일한 처리 원칙을 적용한다.
- OQ-07: 쿠폰 사용 확정 시점은 결제 진행 중이다.

취소 시간의 기준점과 경계 허용 여부, ‘주문 실패’의 의미와 재결제 시 재고 재차감 흐름, 쿠폰 사용의 정확한 확정 시점과 실패·재결제·취소 시 이력 처리는 추가 확인이 필요하다. 사용자 표현을 임의로 구체화하지 않고 Requirements의 Open Question에 남겼다.
