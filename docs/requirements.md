# Requirements

가상의 이커머스 주문·결제 시스템에 대한 초기 요구사항이다. 구현과 테스트의 기준으로 사용한다.

## Requirement Status

| 구분 | 의미 |
| --- | --- |
| Confirmed Requirement | 현재 확정된 구현 및 검증 기준 |
| Open Question | 정책 결정이 필요하며 임의로 구현하거나 기대 결과를 확정할 수 없는 항목 |
| Future Scope | 향후 검토할 범위. 현재 구현 요구사항에 포함하지 않음 |

## Confirmed Requirement

### 상품

- 상품은 이름, 가격, 재고를 가진다.
- 재고가 0인 상품은 주문할 수 없다.

### 주문 수량

- 동일 상품 주문 수량은 최소 1개, 최대 10개다.
- 현재 재고보다 많은 수량은 주문할 수 없다.

### 쿠폰

- `WELCOME10` 쿠폰은 할인 전 주문 금액의 10%를 할인한다.
- 할인 금액은 최대 5,000원이다.
- 존재하지 않는 쿠폰은 사용할 수 없다.
- 한 주문에 쿠폰을 중복 사용할 수 없다.
- 동일 사용자는 동일 쿠폰을 재사용할 수 없다.
- 쿠폰 사용은 결제 진행 중 확정한다. 정확한 처리 시점과 실패·재결제·취소 시 사용 이력 처리는 OQ-07에서 확인한다.

### 주문

- 주문 생성 시 초기 상태는 `PENDING`이다.
- 주문 생성 시점에 주문 수량만큼 상품 재고를 차감한다.
- 미결제 상태에서는 차감한 재고를 유지한다.
- 주문 실패 시 차감한 재고를 즉시 복구하며, 재결제에도 동일한 처리 원칙을 적용한다. 여기서 주문 실패의 의미와 재결제 시 재차감 흐름은 OQ-06에서 확인한다.
- 주문 금액은 상품 가격 × 수량에서 할인 금액을 제외해 계산한다.

### 결제

- 결제 성공 시 주문 상태는 `PAID`가 된다.
- 결제 실패 시 주문 상태는 `PAYMENT_FAILED`가 된다.
- 결제 실패 후 동일 주문에 대해 재결제가 가능하다. 재결제 성공 시 `PAID`가 되고, 실패 시 `PAYMENT_FAILED` 상태가 유지된다.
- 동일 주문에 대해 성공 결제는 한 번만 가능하다.

### 취소

- `PAID` 상태의 주문만 취소할 수 있다.
- 취소 가능 시간은 1시간으로 제한한다. 시간 계산 기준점과 정확히 1시간인 시점의 허용 여부는 OQ-04에서 확인한다.
- 취소 성공 시 주문 상태는 `CANCELLED`가 된다.
- 주문 취소 시 구매한 수량만큼 상품 재고가 복구된다.

## Open Question

아래 세부 정책은 미확정이다. 확정된 원칙과 구분하여 구현 전에 결정하고 이 문서에 반영한다.

| ID | 결정할 질문 |
| --- | --- |
| OQ-04 | 취소 제한 1시간은 주문 생성 시점과 결제 성공 시점 중 언제부터 계산하는가? 정확히 1시간인 시점에도 취소 가능한가? |
| OQ-06 | ‘주문 실패’는 결제 실패를 의미하는가? 재결제 시작 시 재고를 다시 확인·차감하고, 재실패 시 즉시 복구하는 흐름인가? |
| OQ-07 | ‘결제 진행 중’은 결제 요청 시작 시점인가? 결제 실패·재결제·주문 취소 시 쿠폰 사용 이력과 동일 주문의 할인은 어떻게 처리하는가? |

OQ-01, OQ-02, OQ-03, OQ-05는 확정 요구사항에 반영했다. OQ-04, OQ-06, OQ-07은 사용자 답변을 원칙에 반영했으며, 위 세부 사항만 추가 확인이 필요하다.

## Future Scope

현재 등록된 추가 기능은 없다. 향후 제안은 별도로 검토하며, 확정 전에는 구현 범위에 포함하지 않는다.
